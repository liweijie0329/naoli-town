# Skill 学习与实践 — 2025-06-01

## 核心概念

### Skill 是什么
Skill 是给 AI 写的**标准化操作手册**（Markdown 格式），让 AI 在特定场景下稳定执行预设流程。本质是"把人的经验变成 AI 能稳定执行的协议"。

### Skill 的文件结构
```
skill-name/
├── SKILL.md        ← 主入口：name + description（触发词）+ 执行流程
├── references/     ← 参考材料（评分标准、格式契约等）
├── scripts/        ← 确定性工具（校验、生成脚本）
└── assets/         ← UI 模板和资源
```

### 关键元素
- **头部 `---`**：`name`（技能名）+ `description`（触发条件，含中文触发词）
- **正文**：AI 执行的完整流程（常用 Phase 1→2→3 结构）
- **协议格式**：对话版输出自然语言，游戏集成版输出 JSON 指令

---

## 两种 Skill 模式对比

| 维度 | 对话版 | 游戏集成版 |
|------|--------|-----------|
| AI 输出 | 自然语言 | JSON 指令 |
| 适用场景 | 纯 AI 对话 | AI 驱动 App |
| 用户操作 | 打字/语音 | App 内按钮/画布/语音 |
| 判分 | AI 口头宣布 | 写入 item_responses 表 |
| 例子 | "这是什么动物？" → 用户打字"狮子" | `{action:"show_question", options:[...]}` → 用户点按钮 |

## 三类 Skill 架构设计

针对 MoCA 项目，Skill 拆分为三个独立模块：

```
skills/
├── moca-game/       ← 游戏交互（怎么问）
│   └── 15 题的交互协议（show_question, show_feedback 等 JSON 指令）
│
├── moca-clinic/     ← AI 医护评分（怎么判）
│   ├── 文字题判分（DeepSeek/Claude）
│   └── 画图题 AI 视觉复核 + 前端数据交叉验证
│
└── moca-design/     ← 视觉风格（长什么样）
    └── 色板、字号、圆角、阴影、动画规范
```

### 为什么分开
- **改风格**：只改 design，不动业务
- **改评分**：只改 clinic，不动交互
- **加新题**：加 game + clinic，复用 design
- **团队分工**：设计师、医生、工程师各改各的

## 画图题评分优化：分步验证链

### 问题
纯 AI 看图评分容易误判（笔迹淡判成没画、数字歪判成错误）

### 方案
```
Step 1: 前端事件（免费、确定）
  ├── 连线序列、交叉检测、节点数、耗时
  └── 能确定的 → 直接信任，不调 AI

Step 2: AI 视觉复核（仅对不确定项）
  ├── 前端不确定 → 调视觉模型确认
  └── 只问"YES/NO"，不要求 AI 独立判断

Step 3: 综合判分
  ├── 前端+AI 一致 → 给分
  └── 不一致 → 标记人工复核
```

## 和现有 app.js 的关系

- **app.js 已有的**：角色动画、画布渲染、音频播放、UI 交互 — 这些不需要 Skill
- **Skill 补的**：判断逻辑、引导策略、追问机制、评分规则 — 这些 app.js 缺的

Skill 作为 app.js 的"AI 大脑"升级包，通过 JSON 协议与 App 通信。
